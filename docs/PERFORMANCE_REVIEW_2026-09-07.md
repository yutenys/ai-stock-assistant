# 推荐复盘与可靠性修复（2026-09-07）

## 数据范围

- 读取本机 Electron 收藏和模拟交易的副本，不修改真实用户数据。
- 收藏共 38 个标签、373 条记录。排除 `重点关注`、`personal` 的 29 条；另外 11 条加入不足一天，不用于成熟样本反馈。
- 有效成熟样本 333 条，分属 34 个日期/版本标签。同一股票在不同加入日期的收益分别计算，不能把这些记录当作完全独立的实验样本。
- 收益价格来自 2026-09-07 10:23:10 左右取得的腾讯全市场快照，共 5908 只。下表是该时点的历史收藏累计涨跌，不是当前实时收益，也不是新模型收益。
- 收藏收益公式：`(快照价格 / 加入收藏基准价 - 1) * 100%`，不计分红、交易费用、滑点；持有期限不统一，不等同固定期限回测。

## 已修复问题

### 1. 成交量单位错误

新浪日线成交量使用“股”，腾讯报价及内部计算使用“手”。旧回退路径未转换，混合当日报价后量比可能偏差 100 倍，量价估算成交额也会被放大。

现于新浪数据入口统一除以 100。回归覆盖日线合并后的 1.5 倍量比及估算金额；通用日线归一化不重复换算。继续保留 1.5 至 4 倍温和放量范围，不把爆量当作优质突破。

### 2. 真实资金与估算混用

东方财富 `stock/get` 与 `ulist.np/get` 的同名字段不具有相同语义。单股真实资金改用已核验的批量接口读取 `f62/f184`，通过 `f124` 取得数据交易日期。净额可用、买卖分项缺失时保留真实净额，缺失分项保持未知，不再丢弃有效数据后请求大量逐笔估算。

候选股票分批获取当日真实资金，独立存放于 `fundFlowPeriod.current`。历史多日接口失败时明确标记量价代理：

- 代理资金不再给“真实资金确认”正向加分。
- 当日真实净流出且净占比不高于 -3% 时，作为资金转弱信号，同步限制 A/B 推荐和个股入场结论。
- 单日净流入不能证明持续吸筹；仍需要多日资金与结构证据。
- 资金交易日期未知或与分析日期不一致时，不作为当日确认。
- 多日资金失败进入页面警告和详细日志，不能显示为全部来源正常。

主力资金是供应商的大单统计口径，不代表已识别机构身份或未来涨跌方向。

### 3. 亏损组合被正向加分

保留既有负向反馈；平均绝对收益不大于零或正收益比例低于 50% 时，禁止相对同批次跑赢触发正向历史加分。实测最近“震荡洗盘”组存在平均亏损、正收益比例低但相对收益为正的情况，旧逻辑可因此加分。

新模型标识为 `2026-09-07-volume-outcomes-v9`，旧模型推荐缓存不能直接复用成新结果。原有板块资金轮动、新闻时效、公司风险、美股风险修正继续参与；不会因消息标题积极就覆盖资金流出、破位或爆量风险。

### 4. 推荐过少

扩大分散候选历史分析队列：96 -> 160，仍从全市场行情按轮动、强势、横盘、突破、反弹等多路去重选取。不是对 5908 只全部执行完整新闻和财务分析，也不是降低风控门槛凑数量。

板块全量分页按稳定股票/板块代码排序后再本地排名，避免实时资金名次变动造成重复与漏项。实测早间本地反馈请求：158 只历史分析有效、109 只进入多因子核验，A 5 只、B 8 只。后续独立 Electron 空白测试配置在 14:34 左右得到 A/B 各 8 只。最终带本地收藏反馈的复验：160 只历史分析有效、130 只进入多因子核验并取得当日真实资金，A 7 只、B 8 只。时点及反馈输入不同，不作同口径收益比较，也不保证每轮固定数量。

### 5. 大盘刷新阻塞

- 大盘分析移入单个持久 Worker，重用缓存；主进程和界面不执行整段密集筛选。
- 同时触发的刷新共享正在执行的请求，避免重复全市场任务。
- 先更新指数、涨跌家数、成交额，再显示历史、资金消息、公司风险核验进度。
- Worker 最新报价同步回主进程，但不覆盖个股详情已经取得的更新报价。
- 180 秒超时会终止分析线程并返回错误；关闭应用终止线程。

实测完整分析约 50 至 73 秒，不宣称秒级完成。早期指数快照约 0.3 至 0.5 秒到达；真实 Electron 刷新期间通过输入事件成功输入，约 55 秒内 50ms 计时器执行 1097 次，最大间隔 161ms，刷新按钮最终恢复。主进程诊断最大事件循环延迟约 34 至 35ms。最终本地反馈复验耗时 72.5 秒，其中板块/消息阶段等待明显；网络等待仍存在，但不再让用户一直面对没有进度的阻塞界面。

## 接口核验与限制

| 功能 | 本轮核验 |
| --- | --- |
| 利通电子在线搜索 | 返回 603629，中文正常 |
| 实时报价、市值、当前资金 | 返回有效数据；资金使用批量字段口径 |
| 分时、五日、日K、周K、月K | 实际请求通过 |
| 日线技术分析 | 腾讯日线本轮出现 HTTP 501，新浪回退可用且已修正单位 |
| 公司资料与行业 | 珍宝岛资料能识别中药/医药 |
| 全市场、指数、板块资金、美股 | 实际请求返回结构化数据 |
| 行业和复合描述生成 | 手机、白酒、猪肉、地点设施等现有回归覆盖 |
| 多日主力资金 | 仍出现 ECONNRESET；清楚标注不可核验，不伪造连续净流入 |
| 实时消息 | 金十偶有 ECONNRESET，其他现有来源回退；警告保留来源状态 |

公开接口可用性只代表本次本机实测，不能保证后续不受源站或网络影响。无数据不等于零资金、零风险或利好。

## 复现方式

在项目目录依次运行：

```powershell
npx electron tests/read-local-state.cjs
node tests/review-local-performance.cjs
npm test
npm run test:ui
npx electron tests/market-worker-ui.cjs
```

复盘脚本默认重新抓取价格；追加 `--snapshot` 使用已保存的行情快照，保留原采集时间。市场分析阶段仍发起当次请求，因此与收藏快照统计分别标记时间。

私有状态、逐股收益、接口证据及截图仅保存在被 Git 忽略的 `cache/`；操作日志在被忽略的 `logs/`。原收藏与模拟账户没有被覆盖或清理。

验证记录：`npm test` 102/102 通过（约 183 秒，含真实网络请求）；`npm run test:ui` 通过；独立真实 Electron Worker 测试通过；主进程、预加载和渲染脚本语法检查、`git diff --check` 通过。全量大盘网络用例最初超过原 60 秒等待上限，现与应用 180 秒超时边界一致，最终重跑通过，并非取消接口断言。本次不打包、不推送；源码需重启应用生效。

推送前复验：101 项通过，另一项大盘筛选用例触发原 60 秒上限；将该用例同样统一为 180 秒后单项复验通过，耗时约 79 秒，全部筛选断言保留。界面测试再次通过。此次交付仅推送源码、测试及本文档，不包含私有状态、缓存、日志和安装包。

## 后续验证原则

本次证据支持修复数据与筛选错误，不能证明未来收益已经改善。持续保留入场快照，以后续未参与规则调整的日期批次检查固定持有期收益、回撤和基准表现；不要反复在同一批亏损样本上调参并将拟合结果称为收益提升。
