# 公开数据缺失排查（2026-09-10）

## 已修复的代码问题

- 当前资金请求遗漏 `f64/f65/f70/f71`，现按超大单加大单取得真实主力买入/卖出金额。净额仍读取接口原值。
- `invt=2` 把真实零值转成 `-`，使分项求和失败。已移除该格式参数；缺失值不强行填零。
- 北交所 `920xxx` 被错误识别为沪市，导致公司资料查询后缀错误。已统一使用市场识别函数。
- 接入数据中心 `RPT_F10_BASIC_ORGINFO` 和 `RPT_F10_FN_MAINOP`，补齐行业、主营、公司概况和主营构成。构成只取最新报告期，优先产品分类，显示收入及占比；不再把分类编号当产品名。
- 成功公司资料写入本地缓存；接口失联时仅补回缺失字段，标注缓存来源、字段及原获取时间，不把旧资料标为最新。
- 逐日资金改为多来源核验，记录请求天数、实际天数、日期和各来源异常。一日结果不冒充十日；合并实时汇总时不再清空已取得的真实明细。
- 解禁等数据中心响应区分正常无记录与接口业务错误，后者不能被标记为无风险。

第一轮修复后，6 只样本的报价、市值、主力买卖分项、公司资料、财务、风险查询和消息均返回必要数据。随后连续复测中，数据中心连接重置再次出现，公司资料和解禁查询恢复为缺失/未确认。这是已观察到的可用性波动，不能据第一轮成功宣称永久修复。

- 分时、五日、日K、周K、月K均可返回。腾讯日周月接口异常时使用新浪日线或聚合结果，并标明来源。
- 海外三大指数、大盘新闻和板块资金可返回。
- 真实 Electron 刷新 50.7 秒，期间输入可用，50ms 探针最大间隔 111ms，刷新按钮正常恢复。
- 本轮扫描 5911 只，技术分析 158 只，107 只取得真实多日资金汇总。候选被环境风险筛选后为空，不是行情接口返回空。

## 尚未解决

十日逐日主力资金仍无法稳定取得：东方财富历史接口及新浪旧接口连接重置，访客接口曾返回一日，随后返回业务码 100、空数据。新浪 HTTP 检查还收到明确的网络访问策略禁止页面，未尝试绕过限制。独立同花顺、腾讯资金来源也未取得有效响应。

当前可用的是当日资金分项和真实 3/5/10 日累计净额；它们不能推算每日净额或连续流入天数。程序保留缺失提示，不用量价估算替换真实口径。公司资料缓存只在至少成功获取一次后可用；风险未确认不以旧的“无风险”结论覆盖。

用户选择只使用可用公开源，没有新增付费服务或密钥依赖。要完全消除上述外部缺口，还需要网络/数据源恢复，或另一个经过核验且可访问的逐日数据源；本次不能宣称所有数据缺失已解决。
