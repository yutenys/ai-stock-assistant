# 全项目代码检查与修复记录

## 范围

检查主进程行情请求、推荐筛选及回退、板块/资金/消息与个股分析、数值处理、缓存、IPC与窗口配置；检查前端收藏与标签、评分刷新、模拟交易、批量持仓、走势加载与显示；检查preload、HTML安全策略、启动和测试入口。不对生成包、第三方依赖源码、行情缓存及日志进行无关修改。

保留前两轮未提交的策略修改。本轮没有修改真实收藏或模拟持仓数据库，没有打包或推送。

## 本轮修复

| 问题 | 修复 | 验证 |
| --- | --- | --- |
| 筛选成功返回0只仍恢复旧推荐 | 显式记录本轮推荐计算成功，成功筛空不再回退 | 构造成功空结果与旧推荐，验证保持为空 |
| 失败回退旧推荐仍可能保留可入场和消息确认 | 缓存仅供回看，清除入场许可、关闭顶层交易计划、消息待核验；全量接口失败同样降级 | 构造允许入场的旧缓存并验证回退结果 |
| 恢复稳健缓存覆盖当前强势追踪结果 | 保留已生成的强势结果，故障时不恢复旧强势许可 | 验证当前强势结果未被覆盖 |
| 故障回退快照再次被视为新鲜推荐 | 缓存复用拒绝故障回退标记 | 现有缓存回归与新模型失效检查 |
| 个股前端分析缓存无限复用 | 使用分析时间限制2分钟缓存，未知或未来时间不复用 | 过期缓存触发真实请求 |
| 强制刷新被正在执行的普通请求吞掉 | 等待在途请求完成后，执行force=true的新请求 | 可控Promise验证两次请求及最新结果 |
| 个股取消标签勾选后保存仍保留旧标签 | 按当前勾选集合更新该股票成员关系 | 验证移除旧标签且其他股票不受影响 |
| 模拟交易未知方向、数量溢出、旧数字字符串造成错误 | 验证方向及安全整数范围，校验金额和持仓；计算前统一数值类型 | 无效交易不写入，字符串100加仓100得到200 |
| HTTP响应中断可能无法结束等待 | 监听响应error及aborted，进入原有错误/降级链路 | 本地HTTP服务发送部分响应后主动断开 |
| 空白、布尔、数组被Number转换为0或1 | 数值入口只接收有限数字及非空数值字符串 | 覆盖空白、布尔、数组、对象、Infinity与有效0 |
| 市场0家显示为缺失；过期资金被标题称为量价估算 | 区分0与缺失值，资金缓存使用独立标题 | UI回归及显示代码核对 |

推荐模型版本更新为`2026-09-05-consistency-v7`。缓存回退不会重新验证历史行情、资金和消息，故不能保留可执行的入场结论；原始缓存仅用于展示历史信息。

## 验证方式

新增`tests/renderer-logic.test.js`，从实际renderer函数创建隔离测试环境，不复制业务算法。`npm test`同时执行后端与前端逻辑回归；`npm run test:ui`执行Electron界面回归。还执行main.js、renderer.js、preload.js语法检查及git diff --check。

测试包括在线接口和可控离线边界用例。通过测试不代表外部数据源永不失败、覆盖所有行情组合或证明策略盈利；本轮不是第三方依赖漏洞审计。

结果：`npm test` 93项通过、0失败；Electron UI回归通过且`errors`为空；JS语法与差异检查通过。补充的故障缓存复用断言也通过定向复验。
