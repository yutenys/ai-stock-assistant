## 1. 目标与边界

目标是改善可执行、扣成本、满足T+1约束的收益质量，不是增加推荐数量。保留精选最多3只、每日新增最多5只、允许零推荐；但必须区别“无机会”“数据未完成”“程序或口径错误”。不能承诺稳定盈利。

本设计承接2026-11-09短线少而精设计。之前文档标注已落地，但代码核查发现部分契约尚未实现：完整隔夜压力模型、跨日冻结计划生命周期、完整候选漏斗、独立前瞻执行评价等。本次逐项补齐，不以已有测试通过代替策略有效性。

## 3. 为什么今天短线精选为0

当轮recommendationCoverage.shortReboundSelection：精选0、观察24、历史16、当日发布0。缓存只保存观察前20，以下拒绝统计仅针对这20只，不冒充全部24只：

| 原因 | 数量 |
| --- | ---: |
| 公司风险未明确通过 | 20 |
| 压力损失超过3% | 20 |
| 净收益风险比不足2 | 20 |
| 阶段资金证据不足 | 14 |
| 当日资金未确认流入 | 5 |
| 板块资金与扩散未确认 | 2 |
| 费后首阻力空间不足3% | 2 |

不是大盘统一禁止入场：当轮allowNewEntry=true。风险unknown还需细分“未排入核验”“接口失败”“部分结果”“过期”，不能仅凭20个unknown断定都是网络失败。

代码证据与修复方向：

1. main.js在精选前按形态分截40，又在生命周期合并后截40；先截断会漏掉排名较后但证据完整的候选。保留完整轻量候选索引；昂贵查询分批、有上限、有覆盖统计，不能宣称全量核验。
2. lib/short-rebound-selection.js把当前价当入场上限、混用突破触发位与目标位。需要区分确认价、允许入场区间、第一真实阻力、结构失效位。
3. 损失公式为entry/stop-1，而非(entry-stop)/entry，并加固定0.2%成本；称为压力测试却没有隔夜跳空模型。R2使用支撑下方3%缓冲，再要求总损失不超过3%，在常见支撑附近入场场景会形成内在冲突。
4. 风险核验有独立候选集合，最终短线池来自另一集合；需要按代码连接核验状态，量化漏查，而非unknown一律通过。
5. 滚动1/3/5/10日资金全部为正不代表持续流入。须同源同截止时间相减为互不重叠窗口；禁止从汇总反造逐日正流入天数。
6. 所有路线触发文案仍要求收盘放量1.5至4倍，与R2缩量回踩设计不一致。
7. 发布状态跨日直接重置，未完整实现跨日有效期、失效终态与并发读改写；前瞻验证目前只是pending字段，不能视为完整评价闭环。

## 4. 优化方案

### P0：先修数据与评价

- 统一行情、K线、资金、风险、消息的tradeDate/sourceObservedAt/fetchedAt/asOf；缓存刷新不得改变原证据时间。个股分析落后时显示“分析待更新”，重新计算成功后原子替换，不混拼旧结论。
- 漏斗完整保存每个代码、路线、阶段、拒绝原因码及版本；页面只分页，数据不截断。零精选同时展示数据待补数量、机会不合格数量、检查失败数量。
- 分开发布价格观察、触发后观察、可执行模拟收益、真实历史手工持仓；缺少当时可交易证据的记录不可升级为成交。
- 收藏保留首次加入基准与来源；同一股票跨标签描述可以重复，模型收益episode按证券+计划+首次发布去重。保存已移除与失效记录，避免幸存者偏差。
- 新闻解析最终URL、规范标题及事件键去重；政策原文、公司公告、媒体解读分层。保存事件时间、首次可知时间、相关性与过期状态；没有消息不等于利好。

### P1：分路线形成可执行计划

- R1弱势修复、R2趋势回踩、R3整理首启动继续独立核验，不让高分替代必要条件。未知交易阶段不得确认收盘。
- 从已完成K线获取有证据的支撑和压力，标注区间、日期和复权口径。触发价不是目标价；目标空间不足则观察，不外推目标。
- 先以真实结构失效位和成本求允许入场价格区间；当前价超区间则“等待回踩”，不是为了入选抬高止损。回踩之后须再次验证结构和资金，不假设未来一定成交。
- 修正损失公式；正常止损损失与T+1隔夜压力损失分列。使用版本化费用、双边滑点和可核验历史跳空分布；样本不足标记压力未知。原3%/2倍/3%门槛先作为冻结对照，不因今天0只直接放宽。
- R2分别核验回踩缩量和重新转强，不强制回踩日1.5倍放量；突破路线需要温和确认量，超过4倍爆量不精选。盘中量比较同时间历史，不拿半日累计量比较全天。
- 同源资金采用今日、前2日、此前2日、此前5日等非重叠窗口；时间或口径不齐不作差。近期负流入被当天大额翻正的情形标为资金修复待确认，而非持续吸筹。
- 风险查询与候选调度对齐，按待补字段增量核验、并发受控、负缓存短期有效；未知保留观察。资金供应商的“主力”不推断机构真实身份。

### P2：市场与轮动决定优先级

- 对比最近5交易日同时间广度、成交额、涨停次日溢价及回撤路径。缺失锚点不能以当前快照补历史。
- 主题按成员重叠聚类，同一产业链同向暴露合并；排除持仓属性类伪行业。比较净流入/成交额、净流入持续性、剔除前三后扩散、容量股与中位数表现。
- “有资金但只有少数涨”“已拥挤加速”“资金退潮”分开处理。新恢复主题先观察，多次独立快照确认后才提高排序；快照重复不能算持续性。
- 海外风险通过交易日、时区、已结束交易时段映射到国内相关主题。政策与市场消息只提供相关性证据，不与资金字段重复计分，也不突破风险硬门槛。
- 排序优先可执行净空间、压力损失、证据完整度、同周期行业超额，而非涨幅最大或技术分最高。同主题最多1只，多个主题重叠也受限。

### P3：持仓与个股分析闭环

- 入场分析和持仓管理分开。旧仓无原始计划标记“旧仓计划未知”，仅基于当前时点生成后续观察计划，不回填历史止损、伪造本可避免的损失。
- 详情展示短线/波段/中长期、行情与分析时间、当前结构、阶段资金、消息证据、计划状态、失效价、最早可卖日期。禁止过期“已突破”继续覆盖破位事实。
- 持仓增加从买入起最大有利/不利变动、距成本与结构失效距离、盈利回吐、主题集中度；可取得区间历史才计算，缺失不补0。
- 模拟执行遵守T+1、停牌、涨跌停和实际可成交性；收盘信号次交易日买，再下一交易日才可卖。止损只是条件，不保证退出价。
- 报告单列组合收益集中度、去最佳股收益、尾部损失、未执行原因；避免光洋股份一只盈利掩盖多数持仓大幅亏损。

## 5. 验证与上线

1. 固定本周证据夹具：复现精选0/观察24/历史16以及观察缓存截20；新漏斗须能解释每个阶段，未知不得转为通过。
2. 单元反例：风险未排队/失败/过期，混日期、滚动资金掩盖流出、重复新闻、旧分析新报价、触发价误作目标、缩量R2、盘中累计量、跳空越止损、跨日计划过期、失效不复活、并发预算。
3. 集成：候选超过40但后部存在合格者不能因展示截断遗漏；补数任务不阻塞UI；取消、超时、重启恢复不会重复发布。标签与模拟交易数据完全保留。
4. 对照实验：旧v30、仅修正数据与公式、完整改进三组用同证券宇宙和信息截止时间。最近一周只诊断，不作为样本外收益证明；参数修改后冻结新的独立验证段。
5. 延续至少40交易日、100成熟可执行episode的前瞻门槛。少推荐时可能需要更长时间，不人为增加交易凑样本。建立真实影子成交评价通道，仍不授予自动实盘交易权限。
6. 评价1/3/5日净收益、行业超额、中位数、尾部、最大回撤、收益集中度、成交率及置信区间；按路线、市场状态分组。沿用此前费后均值、中位数、Profit Factor与成本加倍压力验收目标，达不到保持实验，不承诺盈利。

实施顺序：P0数据契约与漏斗，P1计划及资金修复，P2轮动排序，P3持仓/详情/报告，最后独立前瞻评价。每步先反例测试，再实现、全量回归及UI验证。正式发布前保留旧策略开关与数据兼容；不回写旧报告，不删除收藏。
