# 收藏规模增长性能优化设计

日期：2026-11-05。状态：待确认，仅设计，未修改业务代码。

## 1. 目标与证据

目标：收藏增加后输入、切换、滚动仍流畅；保存可靠；刷新完成后评分一致；不通过删除收藏、原始计划或降低分析质量换取速度。

只读核验当前本地状态：文件66,209,325字节，约63.1MiB；61个标签，418条成员记录，325只去重股票，单标签最多25只。规模统计不含私人持仓明细。尚未采集运行时CPU火焰图，以下为代码确认的放大路径，不冒称已测得各项耗时。

- `renderer.js:saveState`每次同步JSON.stringify和localStorage写入整个状态，再经IPC发送整个对象；主进程再次序列化并原子写盘。
- `fetchStockAnalysis`每个结果都执行applyAnalysisClassification和saveState。前者遍历所有标签，后者全量保存。
- `favoriteOutcomeRows`每次个股分析都扫描并传输全部收藏反馈。
- `refreshSecondaryData`每10只保存、renderStocks；refreshAnalysisScores还会renderLabels，形成重复绘制。
- `renderStocks`重建主区及详情并调用renderLabels；renderLabels重建标签和股票DOM，重新绑定事件，又启动ensureLabelScores。
- 多次ensureLabelScores调用各自创建并发池，缺少全局排队去重；失败项还可能因重绘再被触发。强制分析等待旧请求后再次发起，容易形成串行重复请求。
- 股票成员包含大型嵌套对象。仅rotationProfiles累计约8.3MB，analysis约3.2MB，analysisViewModel约3.1MB；这不是完整文件的全部体积来源。

## 2. 方案选择

1. 仅加防抖或虚拟列表：成本低，但不能消除63MB状态反复复制；不作为主方案。
2. 分层状态、合并保存、统一任务队列、局部更新：推荐，沿用现有Electron和原子写入基础设施。
3. 全面迁移数据库和前端框架：改动过大，本轮不采用。仅当性能验证证明分层文件方案仍不足再评估数据库。

## 3. 分层状态与安全迁移

用户状态只保存标签身份、成员关系、排序/置顶、加入时间和基准价、收藏快照引用、模拟交易及账户必要字段。禁止用当前分析改写加入时快照。

当前行情和分析按股票代码独立存储；缓存键包含模型版本、数据时间、分析版本。收藏时不可变证据按内容哈希归档，多个成员引用同一证据。同股票在不同标签的基准和时间仍独立。

不得直接删除大字段：先建立现有读取字段清单，再将完整历史证据写入独立文件并校验哈希，最后切换新状态引用。缓存可淘汰，原始收藏和成交证据不可作为缓存删除。

迁移步骤：保留旧文件备份；写新分层文件；核对标签数、成员数、代码集合、基准价、时间、置顶/排序、原计划和持仓数量成本；最后原子提交版本标志。失败或中断继续读取旧版，不覆盖唯一原件。迁移必须幂等并支持回退。

磁盘文件是权威状态。localStorage仅保留压缩后的应急副本，不再镜像行情分析等大型瞬时字段；浏览器配额不足只关闭该副本，磁盘保存仍继续。已有本地数据优先安全迁移，不能因浏览器副本失败造成磁盘数据丢失。

## 4. 保存与刷新调度

用户添加、删除、改标签和模拟交易：串行提交、有revision及磁盘回执；界面成功提示只能在落盘后显示。并发操作不得旧覆盖新。交易事件不做丢弃式合并。

行情/评分：写入独立缓存；合并短时间内同代码变更，不再每股保存全部用户状态。初始合并窗口300ms、最长等待2秒，参数需以测量确认。退出等待必要用户操作落盘；失败明确提示并允许重试，不静默关闭丢数据。

全局唯一分析队列：按代码及分析版本去重，初始总并发3，优先当前详情、持仓、可见标签、其他收藏。等待中请求合并；强制刷新至多追加一次新版本，不逐次排队。失败指数退避，手动重试可提升优先级。

新行情使旧分析标记过期，但不能清空可追溯历史。响应带generation/version，只允许匹配版本更新当前视图；过期结果不能覆盖新结论。切换标签只取消展示订阅，不丢弃其他标签仍需要的任务。

收藏反馈按收藏修订号和市场基准版本计算一次，每批引用同一不可变快照；无需反馈的调用不重复传输。反馈更新必须明确失效，不能缓存过期收益。

## 5. 渲染与索引

建立代码到各标签成员的索引，以及标签到成员列表索引；成员变更时维护，行情更新不反复flatMap全部数据。

将渲染与请求分离：renderLabels不启动网络任务。评分仅更新受影响可见股票的价格、涨跌、评分和状态；标签结构不变不重建标签导航。采用容器事件委托，保留输入焦点、光标、滚动位置和选择状态。

每帧合并一次脏区域更新；后台结果不得重建报告、详情图表、消息页和整个主区。排序变化时按当前规则稳定重排，置顶优先规则保持不变；用户滚动时不随每股到达频繁跳动。

先解决上述放大路径。单标签达到数百只且实测DOM仍成为瓶颈时，再启用窗口化列表；全选、排序、批量保存基于完整数据，不得只作用于可见行。

## 6. 性能验收

在同一机器、相同Electron版本、独立测试目录采集改前/改后数据；使用匿名固定夹具，不覆盖真实收藏。分别测试当前规模、1000及3000个去重代码、多标签重叠、单标签1000行。

记录：状态字节数、JSON/IPC/写盘耗时与次数、DOM节点数、渲染次数、主线程长任务、输入延迟、队列峰值和重复请求、内存及启动时间。日志按批次聚合，不逐卡片刷日志。

目标（待基线实测，不是已实现承诺）：当前规模及1000代码场景，输入响应p95小于100ms、标签切换首屏p95小于200ms；后台刷新不产生超过200ms的应用自身同步任务；网络不计入界面响应指标。每代码同版本最多一个在途请求，总并发不超过3。

同一批行情不写用户主状态；用户确认保存必须有回执。新用户状态不再随重复嵌套行情/分析线性膨胀。3000代码场景测量并报告退化，不靠隐藏数据达标。

正确性回归：跨标签基准不变、排序和置顶正确、编辑焦点不丢、关闭详情不重开、报告页不被后台刷新替换、评分过期明确、旧请求不回写、断网不无限重试、保存失败不报成功、退出和迁移中断可恢复。

## 7. 实施顺序

1. 建立性能夹具和计时基线，核对全字段依赖与状态体积分布。
2. 全局任务去重、失败退避和渲染/请求解耦，先消除重复执行。
3. 分层存储、安全迁移及串行保存回执，消除全状态反复复制。
4. 代码索引与可见区域局部更新，按测量决定是否加入窗口化列表。
5. 全量单测、Electron交互验收、规模压力及故障恢复测试；交付前后性能表和迁移回退说明。

本轮不调整选股算法、风险门槛或推荐数量，不提交真实状态文件和私有证据，不打包或推送。只有代码正确性和性能验收同时通过，才能称为完成。

## 8. 非阻塞与功能兼容补充

### 8.1 明确既有机制，不重复建设

`lib/persistence.js`已按文件串行执行原子写入，具备备份和Windows文件占用重试。本轮保留该基础设施，不全局替换所有存储调用。用户状态专用层负责修订号、合并和回执，不能用另一套无边界队列把大快照积压在内存。

现有每次写入还会JSON.stringify新状态、读取并解析旧状态后备份。异步文件API不代表JSON计算不阻塞。大文件迁移和证据归档的解析、哈希、序列化应在受限工作线程完成；不要把整份63MB对象往返线程或IPC，传路径、版本和小型结果。工作线程异常必须被捕获，不能弹主进程未处理异常。

### 8.2 分阶段发布，不一次切换存储和全部界面

第一阶段只治理重复请求、重复保存触发和重绘，保持原磁盘格式与字段。经同等输入验证后，第二阶段单独引入存储迁移。第三阶段才启用索引及局部渲染。每阶段独立测试、提交及回退；不能以最后一次全量测试替代中途契约验证。

性能新路径的开关仅用于开发和故障恢复，不增加用户必须理解的新设置。不允许新旧渲染器同时刷新，也不允许新旧存储同时成为权威来源。

### 8.3 队列不能阻塞用户操作

- 标签切换、搜索、滚动、编辑不await后台分析。显示已保存数据并标注分析时点，评分未知保持未知。
- 请求必须有超时和有限重试，释放槽位；断网时停止自动重试风暴，手动刷新可重试。
- 多个入口共享全局并发预算，不是各自启动3个任务。当前详情优先但不能无限饿死其他任务；取消一个订阅不能取消其他订阅仍需要的相同请求。
- 旧批次未完成时新刷新只合并待办，不再创建第二个后台循环。仅在真正的新数据版本需要时追加一次重算；过期响应不能写回当前缓存、评分或UI。
- 排队任务保留代码、版本和订阅信息，不保留整份收藏或分析副本；缓存设容量/字节预算，只淘汰可重新获取的数据。
- 返回结果先更新内存脏标记，再按渲染帧和保存周期合并处理。任务异常不能吞掉，批次提示成功/部分成功/失败及覆盖数量。

### 8.4 保存不能拖住输入，也不能误报成功

小型用户操作使用操作ID和预期revision提交，主进程校验后应用；用户删除、改名、买卖等不能以只保留最后快照方式丢弃。界面允许乐观展示，但标记未保存，成功以对应revision回执为准。失败保留待重试操作，不回滚覆盖用户随后操作。

启动先加载小型权威状态和必要可见数据，历史证据按需加载。若启动读取未完成，禁止把临时空状态自动写回磁盘；只暂时禁用依赖收藏的写操作，不禁用全界面。

正常退出仅等待已接受的用户数据提交，不等待行情、新闻、分析或缓存任务。进入关闭状态后拒绝新写操作，停止后台调度；保存超过可配置内部时限时提示重试/取消退出，不能无限静默等待或擅自丢弃数据退出。强制杀进程无法承诺未提交操作落盘，必须保证已确认操作可恢复。

### 8.5 不变的功能契约

| 功能 | 必须保持 |
| --- | --- |
| 多标签收藏 | 同股可存在多个标签；每标签加入时间、累计基准价独立 |
| 评分/今/累 | 同代码最新行情同步；累计仍按各成员原始基准计算 |
| 置顶与排序 | 置顶先于普通排序，缺值置后，同值稳定；无排序保留原序 |
| 标签操作 | 改名、增量保存、删除、编辑选择、右键菜单正常 |
| 搜索与详情 | 搜索不被后台结果清空；关闭详情后后台响应不能重新打开 |
| 图表 | 切换周期、十字线、缩放不因无关股票更新而重置 |
| 模拟账户 | 成交时间、T+1可卖量、数量成本和收益口径不变 |
| 报告 | 历史证据引用可解析；旧报告不因迁移失效 |

排序中的新数据在批次结束或滚动停止后统一重排；用户明确点击排序则立即执行。以首个可见股票代码和偏移恢复滚动，不只保存scrollTop。

### 8.6 迁移回退边界

迁移时旧原件只读保留，新状态引用的证据必须全部写入且校验通过，才能原子切换manifest。不能先删大字段再补证据。迁移期间用户仍可浏览；涉及写操作需经统一网关短暂排队且可见提示，失败退回旧路径处理，不能悄悄忽略操作。

迁移后有新操作时，直接换回旧备份会丢数据，禁止如此回退。先提供兼容导出：由新权威状态重建旧格式，核对当前revision后再切换。未证明可逆之前不删除旧备份，不启用自动清理历史证据。

### 8.7 必须新增的故障与交互测试

1. 连续刷新、切标签、开关详情并发：总并发有界、无重复风暴、旧响应不能覆盖最新数据。
2. 刷新中输入标签名、勾选、滚动及操作图表：焦点、光标、选择、周期和位置保持。
3. 保存中再删除/改名/交易：操作顺序正确、每个回执对应revision，重启结果一致。
4. 磁盘满、权限拒绝、文件占用、线程退出、IPC失败：界面仍可操作，失败提示且不报保存成功。
5. 初始化/迁移各步骤中断及退出：原件完整；下次启动恢复；已确认操作不丢失。
6. 网络无限延迟模拟：超时释放槽位；退出不等网络；切换页面不受影响。
7. 报告页和模拟账户停留期间刷新大量收藏：不触发整页替换，数据口径不变。
8. 至少30分钟持续刷新压力测试：队列可排空，缓存受限，无持续增长的DOM、监听器或内存；记录前后测量结果。

完成标准：上述契约及故障测试全部通过，性能指标达到或明确报告差距。不承诺绝对零bug，以可复现测试、受控发布和可逆迁移降低风险。

## 9. 落地结果（2026-11-05）

- 新增schemaVersion 3用户状态：收藏成员只保留展示、行情、评分、排序及累计收益必要字段；加入时证据按SHA-256内容哈希写入独立证据文件，多标签相同证据去重。
- 旧状态解析、压缩、证据拆分及原子写入放入工作线程；线程返回前先压缩，旧63MB对象不再穿过主进程和渲染进程。证据先写、状态后写，迁移中断仍可读取旧状态和备份。
- 用户保存按revision串行；后台保存300ms合并；明确成功提示等待磁盘回执。localStorage超限不会阻止磁盘保存。
- 个股分析统一使用全局3并发队列，详情、当前标签和后台刷新分级；45秒超时释放槽位；同代码在途请求复用。
- 收藏收益反馈按收藏修订和大盘版本缓存；代码到标签成员建立索引；后台批次不再每股保存并重绘整个主区。
- 当前真实状态只读测量：61个标签、418条成员关系、325个唯一代码。原文件66,209,325字节；压缩状态2,256,181字节，证据1,762,951字节，合计4,019,132字节，预计减少93.9%。首次启动完成迁移前，原文件仍保持不变。
- 3000条收藏关系压力夹具验证标签关系、加入基准和证据完整，压缩后大型瞬时分析字段清除。当前最大标签仅25只，未引入列表窗口化，避免增加滚动、全选和排序回归面。
- 验证：语法检查、44项持久化/渲染定向测试、Electron UI冒烟均通过；完整测试467项通过。真实状态仅只读测量，未在验证中改写。
