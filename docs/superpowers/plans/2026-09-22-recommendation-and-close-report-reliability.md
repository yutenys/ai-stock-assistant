# 推荐恢复、收盘报告校正与近半月策略复盘设计

日期：2026-09-22。实施更新：2026-09-23。数据校验、推荐分层、报告修订及可视化已落地；新增20个交易日的策略效果验证仍须随时间积累，不能预先宣布达标。

**目标：**恢复可信的方案A/B筛选和展示，修正报告交易日期、收盘涨幅及红绿色显示，以可交易、可追溯的样本验证策略，而不是用历史候选凑推荐数量。

**架构：**沿用现有 Electron IPC、行情适配器、推荐工作线程、策略模块和报告模块；增加必要的数据状态与校验，不引入付费接口、外部AI或新后台服务。

**技术栈：**Electron、Node.js、原生前端、JSON/JSONL、本地HTML报告、现有自动化测试。

**适用范围：**仅 `E:\aicodes\ai-stock-assistant`。承接 `docs/POST_CLOSE_REPORT_AND_STRATEGY_DESIGN_2026-09-18.md`；本文的现场验证结果优先于旧文档中的完成状态描述。原有未提交代码和用户数据全部保留。

## 1. 结论与边界

1. 推荐为空既有真实筛选原因，也有新闻生命周期和候选发布问题。不能简单降低评分、放宽爆量或公司风险门槛。
2. 用户贴出的877只是历史观察候选，不是877只通过实时资金、消息和风险核验的推荐。A/B推荐、观察名单和历史待筛池必须拆开统计。
3. 超声电子2026-09-22收盘25.22元、涨幅+0.08%；09-21收盘25.20元、涨幅+7.78%。两个日期都要保留，不能把昨天报告中的正确数值直接改成今天数值。
4. 收盘报告存在可复现的日期校验和空值计算漏洞；即使某次报告数值正确，也需要修复数据契约。
5. 近期收藏均值为正不代表推荐普遍有效：中位数偏低，短线组平均为负，有基准样本多数跑输指数。优先验证入场时点、板块持续性与T+1后的收益。
6. 09-22设计阶段只交付诊断证据；09-23实施保留收藏、模拟交易和旧报告，不原地改写历史数据。

### 不变约束

- 方案A「稳健轮动」、方案B「强势追踪」继续独立，可切换、查看更多、加入收藏；标注短线、波段、中长线。
- 收藏回顾排除「重点关注」「personal」，不删除这些标签；收藏观察收益不是成交收益。
- 不自动下单，不为增加数量把涨停不可买、破位、爆量加速或重大公司风险股票升级为可入场。
- 正常突破放量参考仍为1.5至4倍；缩量回踩、底部结构使用对应量能规则，不要求所有形态都满足突破量比。
- 报告15:30生成，软件未运行时下次启动补报，关闭后不留后台进程。
- 免费接口拿不到的数据保留缺失与来源错误；多日汇总不能冒充逐日资金，量价代理不能冒充真实主力资金。

## 3. 已定位问题

### P0-1：新闻旧权重持续生效，普通负面标题变成全市场否决

代码位置：`main.js` 的 `summarizeNews`、`isMarketWideNews`、`applyEntryContextAssessment`、`recommendationContextBlocked`，以及 `lib/strategy-platform.js` 的 `mergeEventLifecycle`。

- 新取得的12条计算年龄和衰减后，与旧事件合并至50条；保留下来的旧事件未按当前时间重算 `ageHours / recencyWeight / weightedScore`。
- 当前大盘新闻分数-7、调整-16，界面显示的最新6条权重却全为0；用户看不到真正导致否决的旧消息。
- 09-17、09-18消息仍保存约一小时的年龄，实际已过去约96至122小时。
- 同一银行审查事件多个标题重复计分；单家公司“H股相对A股”新闻、韩国或印度央行消息通过宽泛关键词被视为A股全市场风险。
- `大盘消息风险`进入通用禁止条件，同时影响A/B。公司风险核验发生在之后，所以“核验0”不能解释为“无风险”。

只用最新12条重新摘要的敏感性检查为中性、分数0；此检查同时改变了事件集合，不能把差异全部归因于时间衰减。必须在同一完整事件集合上复算，并记录事件级差异。

用户原始数字定位于09-21 11:21:31与11:21:49：122只已补充候选中，`no-chase=68`、`context-risk=54`，严格0、风险核验0；后续追加观察877。09-22最新轮次125只中，`no-chase=30`、`context-risk=95`。现有日志只保留首个拒绝原因，不能证明修正新闻后95只全部合格，也不能承诺恢复多少只推荐。

### P0-2：历史观察候选绕过实时拒绝后发布

代码位置：`main.js` 的 `selectFullMarketScreening`、`buildBackgroundWatchRecommendations`、`buildMarketRecommendations`。

- 历史池877只在实时筛选后追加；被本轮拒绝的代码仍可能从背景池重新进入列表。
- 部分旧信号和高分未按最新行情重算；等待核验被表现成推荐，形态映射不完整导致812只归为“其他”。
- 历史筛选要求同日且缓存年龄小于24小时，跨日后覆盖显示为0；“本地有历史”与“今日完成重算”混为一谈。
- 风险核验0没有把“未尝试”“接口失败”“已查未发现重大事项”区分开。

### P0-3：收盘行情日期、阶段与空值未被强制校验

代码位置：`main.js` 的 `reportClosingQuotes`，`lib/daily-report.js` 的 `finite`、`calculateRecommendationPerformance`、`enrichRecommendation`。

- 当前日行情只检查 `tradeDate`，同日盘中缓存也可被当成收盘；强制生成不等于强制补取正式收盘行情。
- 历史日线缺少最终收盘状态；000823本地09-21日线收盘字段为23.50，实际线上最终收盘为25.20，证明确有盘中暂定日线进入历史库。
- `Number(null)`和空字符串转成0。纯函数复现：参考价10、收盘价null、当时涨幅2%、收盘涨幅null，计算出-1.96%，而不是缺失。
- 报告日期09-22传入09-21的收盘报价，当前函数仍输出“完整”，纯函数已复现。
- 收盘对象存在即视为完整，未逐项校验；结果行丢失关键来源、交易日期和确认信息。
- `entryPermission=blocked`被直接分类为“结构失效”；等待消息/风险核验不等于价格结构已破坏。

## 4. 最小改造架构

```text
公开数据适配器
  -> 字段标准化：交易日期、观察时间、来源、是否最终、质量
  -> 大盘/板块/新闻事件快照（固定asOf）
  -> 历史广筛候选（只表示待筛，不直接发布为推荐）
  -> 当轮行情、量能、资金、消息、公司风险精筛
  -> 形态 + 研究层级 + 入场权限 + 持有周期
  -> A/B发布快照 + 全量拒绝原因 + 待筛队列
  -> 不可变账本
  -> 当日最终收盘行情校验
  -> 每日报告JSON / 软件视图 / 浏览器HTML
  -> 成熟T+1样本复盘与影子策略比较
```

复用现有模块，不新建通用规则引擎。计算函数显式传入 `asOf`，避免回放调用系统当前时间；数据失败只影响依赖该字段的规则。

### 4.1 新闻事件契约

每次合并后对全部保留事件重算年龄、有效性和权重；缓存旧计算值不能直接参与本轮评分。

最小新增字段：`eventId`、`publishedAt`、`firstSeenAt`、`lastSeenAt`、`scope`、`entities`、`severity`、`verification`、`expiresAt`、`effectiveWeight`、`reason`。`scope`区分公司、行业、A股系统性、海外传导与无关；保留原来源链接。

处理顺序：时间解析 -> 同事件去重 -> 主体/市场范围识别 -> 是否仍有效 -> 当前权重 -> 决策影响。没有可核验日期的消息不能按“刚刚发生”获得高权重；旧重大事项通过后续公告更新有效状态，不因简单超过一天就消失。

- 普通负面情绪：影响排序、置信度、可入场条件或建议暴露，不直接清空全市场研究名单。
- 已核实、仍有效的系统性冲击：允许禁止新开仓，但观察列表仍显示其被限制原因。
- 个股重大风险：作用于相关个股；海外事件需说明相关行业和传导链，不用“央行”“A股”两个字直接全市场否决。
- 新闻缺失：显示覆盖不足；需要消息确认的策略不能变成确认入场。不是默认利好，也不应伪造系统性利空。
- UI展示真正影响判断的事件、有效时间、影响方向与链接；最新资讯列表仍按时间倒序，二者用途分开。

### 4.2 候选、推荐和交易权限分离

使用现有字段扩展，不覆盖原始历史记录：

| 维度 | 值与含义 |
| --- | --- |
| 候选来源 | 当轮全市场、历史筛选、用户关注；来源不是推荐质量 |
| 研究层级 | 待筛 / 观察 / 严格；背景池默认待筛 |
| 方案 | A或B，可同时满足，按代码聚合展示归属 |
| 形态 | 反弹、突破蓄势、突破确认、首次回踩、吸筹/洗盘、趋势观察、结构失效 |
| 入场权限 | 条件满足 / 等待确认 / 禁止；附可验证条件和反证 |
| 持有周期 | 短线 / 波段 / 中长线 / 待确认，显示对应评价窗口 |
| 数据状态 | 实时 / 缓存 / 待补充 / 失败；各依赖字段独立标注 |

背景候选不得绕过本轮拒绝规则；已被硬风险拒绝的代码不能因不同来源重新获准。等待核验保留结构标签，不误标为破位。

扫描漏斗至少展示：市场总数、基础合格数、历史可用数、待重算数、本轮精筛完成数、数据不足数、公司风险已核验/未知/未尝试数、A/B严格与观察数、未展示数。首个拒绝原因用于互斥数量对账，全部原因用于解释；不能把多标签原因计数相加当成股票数。

没有合格股票可以显示0，但分清“无符合条件”“资料不足”“任务未完成”“数据源故障”。历史候选另列“待筛池”，不混入正式推荐与收益统计。

### 4.3 扩大有效覆盖，不降低安全条件

保留现有后台全市场历史扫描及有界并发；候选按板块持续性、未覆盖行业、数据新鲜度、当前形态和风险检查状态分批精筛。首批完成可先发布，后续批次续筛，不为等待所有接口冻结界面。

- 区分本地历史覆盖与今日已验证覆盖，跨日不把已存历史显示为0。
- 前一交易日候选可作为今日待筛来源，必须更新行情、最新日线和信号后再发布。
- 为新增板块和未精筛行业保留扫描机会，避免159只长期重复；优先级不能仅由已涨幅度决定。
- 公司风险查询优先覆盖真正可能发布的候选，查不到保留未知，不宣称核验通过。
- 超时后保存续筛游标与缺失原因；前端显示阶段和时间，不把任务超时报告成“没有股票”。

## 5. 策略优化：先验证，再改默认权重

### 5.1 板块轮动看持续性和扩散，不追单日排名

以板块稳定ID及来源分类建立每日观察：真实主力净流入、净占成交额、资金排名分位、资金变化、上涨家数比例、中位涨幅、领涨集中度、成交额、相对市场强度。

- 只有真实逐日数据或已保存的逐日同口径快照，才计算连续流入天数、排名上升和日间加速度。
- 3/5/10日汇总可以判断阶段净额，不能反推每日路径；不同来源和不同板块总体的排名不直接相减。
- 状态区分单日试探、持续流入、扩散确认、拥挤加速、退潮、回流待确认，并列出支持证据和反证。
- 概念重叠按成分交集及共同主题提示集中风险；不将同一只股票的资金在多个概念中重复累加。
- 资金前排不是绝对净流入最大；同时看成交额标准化强度、板块内相对强弱及入场位置。

09-08至22出现化工、电子、设备、医疗和应用方向轮换，说明仅固守少数科技股不够；但每日不同细分榜首也不等于可交易主线已经切换。需用连续可比快照检验，而不是把每日第一名直接推荐。

### 5.2 A/B差异与形态分析

| 路线 | 优先研究对象 | 入场与限制 |
| --- | --- | --- |
| A 稳健轮动 | 持续扩散板块内支撑完整、资金未背离、位置合理的健康滞涨或底部结构 | 不把下跌多等同低吸价值；结构破坏、持续流出或空间不足不入场 |
| B 强势追踪 | 已核验强度和有效突破，等待首次回踩或新一轮合理蓄势 | 不追封板、爆量加速；回踩必须确认关键位、量能及资金承接 |

大盘与个股使用同一份形态、资金、消息和权限结论，不能列表“已突破”、详情“破位”。吸筹/洗盘只在有证据时展示，不把所有等待突破都包装为吸筹。

短线重点验证：相对MA5/10的乖离、前高/压力剩余空间、尾盘回落、日内资金回撤、T+1隔夜风险。波段纳入MA20/30/60结构和板块阶段；中长线再依赖财务质量、主营和估值资料。数据不足时降为待确认，不用短线量比替代中长线分析。

增加明确结论：当前结构、能否入场、触发价格/收盘条件、失效位置、持有周期及消息风险；条件触发是研究信号，不是保证可成交或盈利。

### 5.3 正确的验证口径

1. 本区间已用于诊断，不再称为未见过的样本外测试；09-23以后冻结新旧规则同时影子运行，旧默认不自动替换。
2. 历史重放只用当时已经发布、已获取的数据。缺资金/新闻历史的因子单独列无法回放，不用今日数据补过去。
3. 按交易日滚动验证，保留持有周期重叠的隔离期，不随机拆分同一股票相邻记录。重复股票按代码、入选日、方案和版本聚类，提供去重敏感性。
4. 短线、波段、中长线分别统计固定持有窗口。先沿用既有周期定义；无定义的样本列待确认，不为好看临时改窗口。未到评价期的样本不进入胜率。
5. 收益评价至少包括中位数、平均净收益、跑赢指数/行业比例、最大不利/有利幅度、尾部损失、不可成交比例和数据覆盖；比较同一有效样本集合。
6. 入场采用发布后可执行的价格与订单条件，费用/滑点假设显式冻结。日线无法确认盘中成交先后时标未知，不假定买最低卖最高。
7. 推荐数量不作盈利指标；观察与可入场各自统计，不把未触发条件的观察股涨幅当作策略赚到的钱。
8. 调整默认策略前至少积累20个新增交易日、每条被评估路线30个成熟可交易信号，并提供股票/日期聚类不确定性估计；这是最低证据门槛，不是充分证明。中长线未成熟则继续观察。
9. 在同窗口、同成交假设下比较：中位净超额、尾部风险和执行率不能仅靠少数大涨股改善；未证明稳定改善则不升为默认。

### 5.4 T+1及交易日

盘中买入最早下一交易日卖；盘后推荐最早下一交易日买，再下一交易日卖。最早可卖日按实际成交日计算，停牌、涨跌停或延迟成交继续顺延。

使用 `lib/trade-time.js` 的交易日历，不用自然日加一。2026-09-25至27中秋休市、09-28恢复交易：09-24盘中买入最早09-28卖，09-24盘后信号最早09-28买、09-29卖。交易日依据：[上交所2026年中秋节休市安排](https://www.sse.com.cn/disclosure/announcement/general/c/c_20260915_10832273.shtml)。

## 6. 收盘报告修正设计

### 6.1 收盘数据契约与获取

每个收盘报价至少携带以下含义明确的字段，使用现有命名优先：

```text
code, tradeDate, closePrice, previousClose, changePct
source, fetchedAt, observedAt, sessionPhase
isFinal, finalizationEvidence, quality, errors
```

`isFinal`不是看到本地时间过15:00就设为true。必须校验源交易日、源报价阶段/时间及最终日线证据；无源时间或存在异常时，使用独立来源交叉核验或标为待确认。

- 同日盘中缓存绝不满足收盘要求；强制补报重查缺失和暂定数据，不无差别刷新已经核验的全部历史。
- 历史日线新增暂定/最终状态和确认时间；盘中可以更新暂定条，但正式收盘需再次采集并对账。
- 老数据默认最终状态未知，不一律称错，也不直接用于高可信收盘收益；优先补验报告相关股票和近期推荐、收藏。
- 收盘涨幅优先使用同一报价的昨收和最终价计算；历史按一致复权口径或明确未复权昨收计算。除权、分红等必须使用正确基准，不能拼接不同口径价格。
- 返回null、空白、非有限值均是缺失；价格还需大于0。跨日期、代码不一致、最终状态不明均不得标完整。
- 来源冲突保留两者和原因，不用简单取最大或最新本地写入值；超出舍入误差时报告待复核。

### 6.2 推荐与报告身份

推荐行身份由 `tradeDate + checkpoint + track + batchId + code` 确定。检查点快照必须在目标时刻前发布，行情也必须在可接受时间窗口内；缺真实 `publishedAt` 的旧记录降级并单列，不伪装成10:00推荐。

- 检查点视图允许同股在不同时间出现，明确标题；全日汇总按代码去重，展示首次合格发布及A/B归属，不静默混算。
- A/B表仅纳入真实发布的观察/严格项，历史待筛池只显示覆盖数量与数据质量，不计入推荐收益。
- 观察与可入场分层统计；阻止入场的原因与技术形态分开保存。
- 当日没有新推荐：明确空原因，同时可展示“此前推荐持续跟踪”，保留原始入选日期、价格和方案。例如09-21的超声电子在09-22跟踪表使用09-22最终涨幅+0.08%，不冒充09-22新推荐。
- 持续跟踪采用原定评价窗口，结构失效和退出后保留完成记录，不删除亏损样本；过期样本进入归档。

### 6.3 报告内容与颜色

页首固定显示“交易日YYYY-MM-DD / 生成时间 / 修订 / 完整或部分 / 数据截至时间”。浏览器和软件内展示同一报告JSON，不各自重算收益。

顺序：市场概览 -> 资金轮动 -> 当日A/B推荐 -> 历史推荐跟踪 -> 收藏与模拟持仓 -> 最佳/最差及缺失 -> 数据质量与来源。表头明确：推荐时价格、当时涨幅、当日收盘、当日涨幅、推荐后价格表现、涨幅变化百分点、最早买/卖日期、权限与数据状态。

统一视觉语义：

| 数值 | 文本 | 颜色 |
| --- | --- | --- |
| 正数 | `+0.08%` | 红 `#dc2626` |
| 负数 | `-0.08%` | 绿 `#16a34a` |
| 零或舍入后的负零 | `0.00%` | 中性灰 |
| 缺失 | `--`，附原因 | 中性灰 |

当时涨幅、收盘涨幅、区间表现、超额、板块涨跌、资金净流入/流出、持仓盈亏均使用相同方向规则，并保留正负号，不只靠颜色区分。价格本身不无条件染红绿。参考已有格式函数统一行为，不新增第二套有差异的计算器。

收益公式继续区分：价格表现为 `(最终价/发布参考价-1)*100%`，涨幅变化为两个相同昨收基准涨幅之差；基准不同则不能用涨幅倒算价格表现。新买股票当日浮盈不称为已实现收益。

### 6.4 补报、修订与保存

- 同交易日生成请求共享运行任务，自动与手动触发不同时写报告。需强制补数的请求在当前任务后最多合并执行一轮。
- 使用不可变业务输入哈希，排除抓取耗时等无关波动；内容确有变化才新增修订，记录修订原因和来源差异。
- JSON、HTML成功后才更新索引；失败保留上个可读版本。索引与报告串行提交，不能仅依赖单文件重命名。
- 旧报告不覆盖，新增校正修订。缺当时推荐、消息或持仓快照的补报标部分完成，不能用当前收藏回填历史成员。
- 收藏事件及持仓按报告截至时间重建；缺历史变更记录时明确不可重建，不包含报告日期之后添加的股票。
- 对EPERM/EBUSY做有界重试和写入者诊断；以主进程为同数据目录写入入口，避免工作线程/多窗口竞争。先确定占用原因，不盲删tmp或关闭用户进程。

## 8. 验收清单

### 8.1 确定性测试

| 用例 | 必须结果 |
| --- | --- |
| 旧新闻合并后跨96小时重算 | 年龄、有效权重按本轮asOf更新；不能保留一小时前的年龄 |
| 同事件三条不同标题 | 关联同事件，不累计三次系统风险；保留来源 |
| 单股H股折价、无传导的海外央行新闻 | 不成为A股全市场硬否决 |
| 已确认重大公司/系统风险 | 禁止相关新入场；修复不能取消有效风控 |
| 最新6条与实际决策事件不同 | 展示另一个“影响判断的消息”区域及解释 |
| 背景候选命中no-chase或公司硬风险 | 不从历史列表重新升级为可入场 |
| 122只的互斥拒绝计数 | 68+54=122；风险核验0明确为未执行，不称风险为0 |
| 多日汇总125只、逐日不足 | 明确各自覆盖；不输出连续10日流入 |
| 000823，09-22最终25.22，昨收25.20 | 收盘涨幅+0.08%，红色，日期09-22 |
| 000823，09-21最终25.20，昨收23.38 | +7.78%，仍属于09-21，不被今天值覆盖 |
| 报告09-22输入09-21报价 | 拒绝用于当日收盘，记录日期不匹配 |
| 同交易日10:02暂定日线 | 不作为收盘最终值，触发补验 |
| null、空串、NaN或无报价 | `--`，无收益、无假0、不标完整 |
| 权限blocked但趋势未破 | 显示具体限制，不能分类为结构失效 |

| 注入EPERM、接口超时、源间冲突 | 有界恢复或真实部分失败，不覆盖可用旧报告 |
| 重新生成历史报告 | 不混入以后新增收藏、当前新闻或新的推荐 |
